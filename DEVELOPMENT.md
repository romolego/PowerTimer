# Разработка и проверка

## Код

| Файлы | Назначение |
| --- | --- |
| `Core.cs` | Состояния таймера, монотонный отсчёт, восстановление, однократное завершение; не зависит от WPF. |
| `Program.cs` | Запуск, блокировка экземпляра, передача повторного запуска. |
| `App.cs` | WPF, трей, планирование обновлений, интеграция с Windows, маршруты API. |
| `Storage.cs` | Ограниченное чтение и атомарная запись JSON, защита каталога. |
| `Preferences.cs`, `SettingsUi.cs`, `Theme.cs` | Валидация настроек, черновик настроек, тема, автозапуск. |
| `DurationInput.cs` | Дробные часы/минуты с точкой или запятой, формат короткой длительности. |
| `Api.cs`, `Client.cs` | HTTP на loopback с ограничениями; клиент и CLI. |
| `*.xaml` | Окна и общие стили. |
| `TestHarness.cs` | Диагностика только в `--test`: реальные обработчики элементов WPF и рендер окон. |

Изменения двигателя выполняются на UI-потоке. HTTP обрабатывается ограниченным числом фоновых работников; мутации передаются в Dispatcher и отклоняются, если ожидали более трёх секунд. Ожидание соединения блокирующее, без опроса. Заголовки читаются буфером, а не системным вызовом на каждый байт.

Отсчёт использует Stopwatch. Без работающего таймера DispatcherTimer остановлен (кроме однократного удаления сообщения об ошибке). Хранение таймера обновляется при изменении состояния и системного времени; настройки записываются только при изменении содержимого. Ошибка записи сохраняет предыдущий целый файл и видна пользователю. Это не гарантия сохранности при аппаратном повреждении диска.

Файловая блокировка в каталоге данных защищает от повторного запуска из другой папки и другого сеанса того же пользователя. Именованный mutex оставлен для совместимости с прежними версиями. Тестовый экземпляр использует отдельные каталог, блокировку и порт.

## Проверки

`build.ps1` собирает с оптимизацией и превращает предупреждения компилятора в ошибки. `run-tests.ps1` запускает и завершает только тестовый экземпляр. Уже запущенный тестовый экземпляр нужно закрыть перед выполнением набора. Продукционный экземпляр не затрагивается.

- `CoreTests.cs`, `ReliabilityTests.cs`: состояния и границы таймера; замена/отмена при завершении; скачки часов; некорректные данные; дробный ввод; атомарность настроек и сохранения; HTTP-аутентификация, таймауты, ограничения и закрытие соединений.
- `integration_tests.py`: реальный локальный API, параллельные чтения, истечение и отмена с подставной командой выключения.
- `ui_flow_tests.py`: выбор, старт, пауза, продолжение, отмена, модальное окно, виджет, рендер.
- `settings_integration_tests.py`: 3,5/3.5 часа, валидация, сохранение и отмена темы, семь интервалов, настройки виджета без сброса таймера.
- `instance_tests.py`: одновременные запуски и копия EXE из другой папки; тот же PID и остаток; возврат диалога.
- `stress_tests.py`: 1000 запросов состояния, 100 циклов настроек/паузы/продолжения, контроль роста системных дескрипторов и отсутствия опроса в простое.
- `lifecycle_tests.py`: принудительное завершение именно тестового процесса, восстановление на паузе, истёкшее/повреждённое состояние, смена ключа, просроченные запросы, задержка UI, гонка выхода.

Взаимодействия с интерфейсом вызывают обработчики настоящих WPF-кнопок; они проверяют видимость и доступность элемента. Это не тест физического клика мышью. Тестовые маршруты недоступны обычному экземпляру.

CI выполняет сборку и этот набор на Windows. Для выпуска используйте `package.ps1`; бинарные файлы помещаются в Releases, а не в git. Токены, пользовательские настройки, журналы и временные файлы не входят в репозиторий.

## Совместимость

Старые восемь интервалов мигрируют в семь, восьмое место занимает своё время. `addSeconds` оставлен как устаревшее поле API для совместимости клиентов, но интерфейс его не использует; `/v1/extend` получает длительность явно. API v1 сохранён.
